# 贪心算法的核心证明技巧
在具体看算法之前，文献总结了三种证明贪心算法最优性的标准技巧：
1.  **贪心始终领先 (Greedy algorithm stays ahead)**：证明在算法的每一步，贪心解的当前状态都至少和任何其他算法（包括最优解）一样好。
2.  **交换论证 (Exchange argument)**：通过逐步将任何给定的解（包含最优解）转化为贪心算法找到的解，且在转换过程中不降低解的质量，从而证明贪心解是最优的。
3.  **结构论证法 (Structural bound)**：发现一个简单的“结构”下界（或上界），证明所有可能的解必然受到该界限的限制，然后证明贪心算法恰好能达到这个界限。

### 二、 区间与调度问题 (Interval & Scheduling Problems)

#### 1. 区间调度 (Interval Scheduling)
*   **概念**：给定一组作业，每个作业 $j$ 有开始时间 $s_j$ 和结束时间 $f_j$。如果两个作业不重叠，则它们是兼容的。目标是找到最大的互相兼容的作业子集。
*   **贪心算法**：**最早结束时间优先 (Earliest finish time first)**。按结束时间升序排列作业，只要与已选择的作业兼容就选择它。时间复杂度为 $O(n \log n)$。
*   **关键证明 (贪心始终领先 / 反证法)**：
    *   假设贪心解不是最优的。设贪心算法选出的作业集为 $i_1, i_2, \dots, i_k$，某最优解选出的作业集为 $j_1, j_2, \dots, j_m$。
    *   假设前 $r$ 个作业两者相同（即 $i_1 = j_1, \dots, i_r = j_r$），且 $r$ 是可能的最大值。
    *   由于贪心算法总是选择最早结束的作业，因此第 $r+1$ 个贪心作业 $i_{r+1}$ 的结束时间一定早于或等于最优解的第 $r+1$ 个作业 $j_{r+1}$。
    *   如果我们在最优解中用 $i_{r+1}$ 替换 $j_{r+1}$，由于 $i_{r+1}$ 结束得更早，它绝对不会与 $j_{r+2}$ 产生冲突。这使得我们得到了一个同样大（最优）的解，但它与贪心解有 $r+1$ 个相同的作业，这与 $r$ 是最大值矛盾。

#### 2. 区间划分 (Interval Partitioning)
*   **概念**：给定一组讲座，目标是使用最少数量的教室来安排所有讲座，使得同一教室内没有时间重叠的讲座。
*   **深度 (Depth) 概念**：在任何给定时间点同时重叠的最大区间数。显然，**所需教室数量 $\ge$ 深度**。
*   **贪心算法**：**最早开始时间优先 (Earliest start time first)**。按开始时间升序排列讲座；将其分配到任何一个兼容的教室，如果没有兼容的，则分配一个新教室。时间复杂度为 $O(n \log n)$。
*   **关键证明 (结构界限)**：
    *   贪心算法绝不会将两个不兼容的讲座安排在同一个教室。
    *   假设贪心算法分配了 $d$ 个教室。开启第 $d$ 个教室是因为当时有一个讲座 $j$ 与前面 $d-1$ 个教室中的所有讲座都不兼容。
    *   因为是按开始时间排序的，所以这 $d-1$ 个讲座的开始时间都不会晚于 $s_j$。而且它们与讲座 $j$ 不兼容，意味着它们在 $s_j$ 时刻都还没有结束。
    *   因此，在 $s_j + \epsilon$ 时刻，有确切的 $d$ 个讲座相互重叠，即**深度为 $d$**。结合前面的结构界限，任何调度方案至少需要 $d$ 个教室，因此贪心解是最优的。

#### 3. 最小化延迟调度 (Scheduling to Minimize Lateness)
*   **概念**：单个资源处理作业，作业 $j$ 需用时 $t_j$，截止时间 $d_j$。若作业在 $f_j$ 结束，延迟 $\ell_j = \max\{0, f_j - d_j\}$。目标是最小化最大延迟 $L = \max \ell_j$。
*   **贪心算法**：**最早截止时间优先 (Earliest deadline first)**。按截止时间 $d_j$ 的升序调度作业。
*   **关键证明 (交换论证)**：
    *   *定义逆序 (Inversion)*：如果作业 $i$ 安排在 $j$ 前面，但 $d_i > d_j$，则称之为逆序。贪心调度没有空闲时间也没有逆序。
    *   如果某个无空闲时间的最优调度包含逆序，那么它必然包含一对**相邻的逆序对**。
    *   *关键主张*：交换这对相邻的逆序作业，会使逆序数减1，并且**不会增加最大延迟**（因为交换后 $j$ 会更早完成，其延迟变小或不变；而 $i$ 虽然变晚了，但它的完成时间 $f_i'$ 就是原来 $j$ 的完成时间 $f_j$，此时 $\ell_i' = f_i' - d_i = f_j - d_i \le f_j - d_j = \ell_j$，即不超过交换前两者的最大延迟）。
    *   若假设 $S^*$ 是逆序对最少的最优解且含有逆序，交换后得到同样最优但逆序对更少的解，引发矛盾。

#### 4. 选择断点 / 加油站问题 (Selecting Breakpoints)
*   **概念**：汽车沿路线行驶，满油续航为 $C$。要求在途中加油次数最少。
*   **贪心算法**：每次尽可能走得最远再加油。
*   **证明 (反证法 / 贪心始终领先)**：假设贪心算法选的断点为 $g_0, \dots, g_p$，最优解为 $f_0, \dots, f_q$，若前 $r$ 个断点两者相同，则在第 $r+1$ 步时，贪心算法走的距离 $g_{r+1}$ 严格大于最优解的 $f_{r+1}$。如果让最优解也走那么远，并不会增加后面的加油次数，从而得出贪心不劣于任何解。

### 三、 硬币找零与缓存最优替换 (Coin Changing & Optimal Caching)

#### 1. 硬币找零问题 (Coin Changing)
*   **问题目标**：给定一组货币的面值（如 1, 5, 10, 25, 100），设计一种方法，在给顾客找零时使用**最少数量**的硬币。
*   **出纳员算法 (Cashier's Algorithm)**：即该问题下的贪心算法。在每一次迭代中，总是**贪心地选择面值最大**且不超过当前需要找零总额的硬币。
    *   *算法步骤*：首先将硬币面值从小到大排序（$c_1 < c_2 < \dots < c_n$）。当还需要找零的金额 $x > 0$ 时，找到满足 $c_k \le x$ 的最大面值 $c_k$，将其加入找零集合，并将 $x$ 更新为 $x - c_k$，以此类推。
-   **最优解的结构限制**：证明的核心在于分析**任何一个最优解（Optimal Solution）在硬币组合上必须满足以下限制**。如果不满足这些限制，我们总能用大面值硬币替换小面值硬币，从而得到硬币数更少的解：
	*   **1美分 (Pennies) 数量 $\le 4$**：如果有5个1美分，可以直接换成1个5美分，硬币数更少。
	*   **5美分 (Nickels) 数量 $\le 1$**：如果有2个5美分，可以换成1个10美分。
	*   **25美分 (Quarters) 数量 $\le 3$**：如果有4个25美分，可以换成1个100美分。
	*   **5美分 + 10美分 (Nickels + Dimes) 的组合数量 $\le 2$**：
	    *   如果有3个10美分（30美分），可以换成1个25美分 + 1个5美分（数量从3降到2）。
	    *   如果有2个10美分 + 1个5美分（25美分），可以直接换成1个25美分（数量从3降到1）。
-   **小面额硬币的总和上限**
	基于上述最优解必须满足的限制，我们可以计算出在最优解中，**比某种面值 $c_k$ 小的所有硬币，它们能凑出的最大总和**：
	*   比 5美分 小的硬币（只有1美分），最多能凑出 $4 \times 1 = \mathbf{4}$ **美分**（$< 5$）。
	*   比 10美分 小的硬币（1和5美分），最多能凑出 $4 + 5 = \mathbf{9}$ **美分**（$< 10$）。
	*   比 25美分 小的硬币（1、5和10美分），根据前面的限制（5美分和10美分最多2个），最多只能是2个10美分+4个1美分，总和为 $\mathbf{24}$ **美分**（$< 25$）。
	*   比 100美分 小的硬币，最多能凑出 3个25美分 + 24美分 = $\mathbf{99}$ **美分**（$< 100$）。
- **归纳证明得出结论**
	假设我们要找零的金额 $x$ 满足 $c_k \le x < c_{k+1}$（即 $c_k$ 是当前能用的最大面值）。
	*   由于比 $c_k$ 小的所有面值硬币在最优解中能凑出的最大总和**永远严格小于** $c_k$（例如，没有25美分硬币帮忙，其他小硬币最多只能凑出24美分），所以**最优解如果不使用 $c_k$，就根本无法凑出 $x$ 这个金额**。
	*   因此，任何最优解**必然（Must）**包含贪心算法所选择的最大面值硬币 $c_k$。
	*   选择了 $c_k$ 后，问题缩小为找零 $x - c_k$ 并在剩下的金额上继续归纳，这证明了贪心算法不仅是正确的，而且是最优的。

> 贪心算法的成功**严重依赖于上述特殊的面值属性**。对于**任意给定的面值体系，出纳员算法很可能无法得到最优解**，甚至在没有1单位面值的情况下无法给出有效解

#### 2. 最优离线缓存 (Optimal Offline Caching)
-   **问题定义**：
	*   **基本设定**：假设我们有一个容量为 $k$ 的缓存（Cache），可以存储 $k$ 个数据项。我们面临一个由 $m$ 个数据项请求组成的序列：$d_1, d_2, \dots, d_m$。
	*   **缓存命中（Cache hit）**：如果请求的数据项已经在缓存中，则无需进行替换。
	*   **缓存缺失（Cache miss）**：如果请求的数据项不在缓存中，我们必须将其调入缓存；如果此时缓存已满，就**必须驱逐（Evict）**缓存中现有的某一个数据项。
	*   **目标**：设计一种驱逐调度方案，使得在处理完整个请求序列后，**缓存缺失的次数（即驱逐次数）降到最低**。
-   **最优贪心算法：最远未来策略（Farthest-In-Future, FF）**
	*   **核心算法 (Farthest in Future算法)**：当缓存已满且发生缓存缺失时，**总是驱逐那个在未来最晚被再次请求的数据项**（或者是未来永远不再被请求的数据项）。
	*   *直观理解*：如果一个数据项在很远的未来才会用到，那么把它留在缓存中会白白占用宝贵的空间，不如把它踢出，给近期高频使用的数据腾出位置。
-   **规约调度 (Reduced Schedule)**：**只有在请求某个数据项且该数据项不在缓存中时，才将其加载进缓存**。也就是说，系统不会在没有请求的时候“提前”或“无故”将数据装入缓存。
*   **关键主张**：对于任何一个非规约调度（Unreduced Schedule）$S$，我们都可以将其转化为一个规约调度 $S'$，且 **$S'$ 的缓存缺失次数绝对不会超过 $S$**。
    *   *改造方法*：如果 $S$ 在没有请求的情况下提前调入了数据 $d$，并驱逐了 $c$。
        *   情况A（$d$ 在下次被访问前又被驱逐了）：$d$ 白白占用了空间。我们可以改造调度，当初干脆不调入 $d$（把 $c$ 留在缓存里），这样确实能减少或保持相同的缺失数。
        *   情况B（$d$ 在被驱逐前终于被请求了）：我们可以推迟 $d$ 的调入，直到真正请求它的那一刻再调入，缺失数同样不会增加。
-   **交换论证 (Exchange Argument)**：证明存在一个最优的规约调度 $S$，它与我们的 FF 贪心算法在每一步的选择上都是一致的。
	*   **归纳假设**：假设存在一个最优调度 $S$，在处理 $j$ 前，它与 FF 算法（记为 $S_{FF}$）的**缓存内容完全相同**。在 $j$ 时，$d$ 不在缓存中，$S_{FF}$ 按照“最远未来策略”驱逐了 $f$，但最优解 $S$ 驱逐了 $e$（$f \neq e$）。
	*   **消除分歧（最早分歧时刻）**：找到最小的 $j' > j$ ，此时 $S$ 与 $S_{FF}$ 再次发生分歧（假设在 $j'$ 访问 $g$ ） 
	*   **消除分歧（将最优解 $S$ 转化为与 FF 一致的 $S'$）**：
	    *   **情况 1 ($g = f$)**：这在 FF 中是**不可能发生**的。因为 FF 选择的 $f$ 是最远未来的，所以在请求 $f$ 之前，必定已经先请求了 $e$。
	    *   **情况 2($g = e$)**：$S$ 之前驱逐了 $e$，所以 $S$ 此时发生缺失，必须驱逐一个元素 $e'$ 并调入 $e$。这时候，如果在 $j$ 时刻 $S$ 没有驱赶 $e$ 而是像 $S_{FF}$ 一样驱赶了 $f$，那么 $S$ 因为一直保留着 $e$，所以，在 $j'$ 时反而还少了一个miss。
	    *   **情况 3 ($g \neq e, f$)**：那么 $S$ 如果在 $j$ 时刻驱逐了 $f$ ，而且在 $j'$ 时刻驱逐的元素与 $S_{FF}$ 一致，那么二者的 miss 数一致，而且缓存也一致了。
	*   **结论**：通过上述交换操作，我们把最优调度 $S$ 强行“纠正”成了与 FF 算法在第 $j+1$ 步一致的 $S'$，且在整个调整过程中，**$S'$ 的缓存缺失次数没有增加**。不断重复这个过程，最终我们可以把任何最优解变成 FF 算法生成的解，从而无可辩驳地证明了 **FF 算法就是最优解**。

### 四、 单源最短路径 (Shortest Paths)

#### 1. Dijkstra 算法
-   **问题定义**：Dijkstra 算法是解决**单源最短路径问题** 的经典贪心算法。给定一个有向图 $G = (V, E)$，起点为 $s$，并且假设**所有的边权（长度） $\ell_e \ge 0$**，其目标是找到从起点 $s$ 到图中所有其他节点的最短有向路径。
	*   **状态维护**：算法维护一个已探索节点集合 $S$，对于 $S$ 中的每一个节点 $u$，算法都已经确定了从 $s$ 到 $u$ 的真实最短路径长度 $d[u]$。
	*   **初始化**：集合 $S$ 初始只包含起点 $s$（即 $S = \{s\}$），且 $d[s] = 0$。
	*   **贪心选择规则**：在每一步中，算法环顾集合 $S$ 的“边界”，寻找一条从集合 $S$ 内部指向集合 $S$ 外部节点 $v$ 的边 $e = (u, v)$。对于所有这样的节点 $v$，计算一个**预估最短距离 $\pi(v)$**：$$\pi(v) = \min_{e=(u,v) : u \in S} (d[u] + \ell_e)$$    算法总是贪心地选择那个使得 $\pi(v)$ 最小的未探索节点 $v$，将其加入集合 $S$，并正式确立 $d[v] = \pi(v)$。
-   **最优性证明（数学归纳法，贪心始终领先）**：证明的核心在于说明：**当算法把节点 $v$ 加入集合 $S$ 时，它找到的路径长度 $\pi(v)$ 绝对是所有可能从 $s$ 到 $v$ 的路径中最短的**。
	-   **证明过程：**
	1.  **归纳假设**：假设对于当前集合 $S$ 中的每一个节点 $u$，算法算出的 $d[u]$ 确实是最短路径长度（当 $|S| = 1$ 即只有起点 $s$ 时显然成立）。
	2.  **考虑新节点 $v$**：假设算法接下来选中了节点 $v$ 并将其加入 $S$，此时利用的边是 $(u, v)$。这意味着算法找到了一条长度为 $\pi(v) = d[u] + \ell(u, v)$ 的 $s \to v$ 路径。
	3.  **反证比较**：假设在图中存在另一条从 $s$ 到 $v$ 的路径 $P$。我们需要证明路径 $P$ 的长度绝对不会小于 $\pi(v)$。
	4.  **跨越边界的边**：因为起点 $s$ 在集合 $S$ 内，而 $v$ 最初在集合 $S$ 外，路径 $P$ 必然在某一步**第一次离开集合 $S$**。设 $(x, y)$ 是路径 $P$ 中第一条离开 $S$ 的边（即 $x \in S$，$y \notin S$），并设 $P'$ 是路径 $P$ 中从 $s$ 到 $x$ 的那段子路径。
	5.  **核心不等式链**：
	    *   因为图中的所有边权均为非负（**$\ell_e \ge 0$**），所以路径 $P$ 的总长度 $\ell(P)$ 必然大于等于它走到 $y$ 时的长度：$\ell(P) \ge \ell(P') + \ell(x, y)$。
	    *   根据归纳假设，$x$ 在集合 $S$ 内，所以 $\ell(P') \ge d[x]$。代入得：$\ell(P) \ge d[x] + \ell(x, y)$。
	    *   根据算法定义，$d[x] + \ell(x, y)$ 正是节点 $y$ 此时的候选距离 $\pi(y)$。所以 $\ell(P) \ge \pi(y)$。
	    *   最后，**最关键的一步**：为什么算法此时选择了 $v$ 而不是 $y$ 加入集合 $S$？正是因为 $v$ 是所有边界外节点中 $\pi$ 值最小的！所以必定有 $\pi(y) \ge \pi(v)$。
	    *   连接所有不等式，得出结论：**$\ell(P) \ge \pi(v)$**。这证明了不存在任何比当前贪心选择更短的路径，算法是绝对最优的。
	*(注：从上述推导中的 $\ell(P) \ge \ell(P') + \ell(x, y)$ 可以明显看出，**如果没有“边权非负”的前提，这个不等式就会破裂**，这也解释了为什么 Dijkstra 算法无法处理包含负权边的图。)*

-  **高效实现与时间复杂度分析**：如果每次加入新节点时都去重新遍历 $S$ 中的节点来计算 $\pi(v)$，算法将极其低效。为了在 $O(m \log n)$ 时间内完成计算，Dijkstra 引入了两个关键优化：
	  **1. 动态维护最短距离估计 $\pi[v]$**
		算法不每次重新计算，而是为每个未探索的节点 $v$ 显式维护一个数组 $\pi[v]$。当一个新节点 $u$ 被加入集合 $S$ 时，可能会有经过 $u$ 到达其他节点 $w$ 的更短路径出现。因此，算法只需遍历**从 $u$ 出发的每一条边 $e = (u, w)$**，并尝试“松弛 (Relax)”更新 $w$ 的最短距离估计：$$\pi[w] = \min(\pi[w], d[u] + \ell_e)$$	如果 $d[u] + \ell_e < \pi[w]$，则找到了到 $w$ 的更短路径，更新 $\pi[w]$。
		
	  **2. 使用优先队列 (Priority Queue)**
		算法使用一个以 $\pi[v]$ 为键值的**最小优先队列 (Min-Oriented Priority Queue)** 来存储所有未探索的节点。
	  *   **Extract-Min（弹出最小元素）**：每次寻找 $\pi(v)$ 最小的节点只需从优先队列中弹出堆顶元素。图中有 $n$ 个节点，每个节点刚好被加入集合 $S$ 一次，因此发生 $n$ 次 `Extract-Min` 操作。
	  *   **Decrease-Key（减小键值 / 更新优先级）**：当节点 $u$ 被加入 $S$ 并扫描其邻接边 $(u, w)$ 时，如果 $\pi[w]$ 被成功更新为更小的值，则需要在优先队列中降低 $w$ 的优先级。由于图中共包含 $m$ 条边，每一条边最多触发一次更新，因此 `Decrease-Key`（或 `Change-Key`）操作的总次数上限为 $m$ 次。
		**时间复杂度汇总：**
	  *   **使用二叉堆 (Binary Heap)**：`Extract-Min` 耗时 $O(\log n)$，`Decrease-Key` 耗时 $O(\log n)$。总耗时为 $O(n \log n + m \log n) = \mathbf{O(m \log n)}$。这对于稀疏图非常高效。
	  *   **使用斐波那契堆 (Fibonacci Heap)**：可以将 `Decrease-Key` 的摊还成本降为 $O(1)$，此时算法的理论最优时间复杂度可达到 $\mathbf{O(m + n \log n)}$，这在处理节点极多且非常稠密的图时具有显著优势。
- **算法的扩展应用**：得益于 Dijkstra 算法底层的代数结构（闭半环 Closed Semiring），该贪心策略及其证明不仅适用于求加法累加的最短路径，经过简单修改后，还能解决同类网络流与路径选择问题：
	*   **无向图最短路径**：将每条无向边视为两条同等长度的相反有向边，在处理节点 $u$ 时考察所有与 $u$ 关联的边即可。
	*   **最大容量路径 (Maximum capacity paths)**：如果目标是找到一条路径，使得路径上最窄的瓶颈（即最小边权）尽可能宽，只需将更新规则改为 $\pi[v] = \max(\pi[v], \min(\pi[u], c(u, v)))$。
	*   **最高可靠性路径 (Maximum reliability paths)**：如果边权代表不发生故障的概率 $\gamma$，目标是求整条路径不发生故障的最大概率（概率连乘），只需将更新规则改为 $$\pi[v] = \max(\pi[v], \pi[u] \times \gamma(u, v))$$。

### 五、 最小生成树 (Minimum Spanning Trees, MST) 及其应用

#### 1. 最小生成树 (MST) 的关键定理与结构性质
*   **切集性质 (Cut Property)**：对于图中任意节点划分 $S$ 和 $V-S$ 构成的切集，如果一条边 $e$ 是该切集中代价最小的边，那么一定存在一个包含 $e$ 的最小生成树。
    *   *证明 (交换论证)*：如果 MST $T^*$ 不包含 $e$，那么将 $e$ 加入 $T^*$ 会形成一个环 $C$。因为 $e$ 跨越了切集，环 $C$ 上必然存在另一条边 $f$ 也跨越了该切集。因为 $e$ 是切集中代价最小的，所以 $c_e \le c_f$。用 $e$ 替换 $f$，我们得到了新的生成树 $T'$，且代价不增加。
![[Pasted image 20260421171449.png]]
*   **环性质 (Cycle Property)**：对于图中任意环 $C$，如果边 $f$ 是该环中代价最大的边，那么 MST 绝对不会包含 $f$。
    *   *证明 (交换论证)*：假设 MST $T^*$ 包含了 $f$。将 $f$ 从 $T^*$ 中删除会将树分为两个连通分量，形成一个切集 $S$。因为 $f$ 在环 $C$ 上，环上必有另一条边 $e$ 也跨越了这个切集。因为 $f$ 是环上代价最大的，所以 $c_e \le c_f$。用 $e$ 替换 $f$ 可以得到代价不增加的生成树。
![[Pasted image 20260421171511.png]]


#### 2. 三大经典的 MST 贪心算法
凭借 Cut 和 Cycle 这两个性质，演化出了三种著名的贪心算法（它们都会生成 MST）：
*   **Kruskal 算法**：按权重升序遍历边，如果不形成环就加入树。本质上不断应用环性质（如果成环说明它是当前环中最长的边，抛弃）和切集性质。借助并查集 (Union-Find) 复杂度为 $O(m \log m)$ 或 $O(m \log n)$。
*   **Prim 算法**：从某个源点 $s$ 开始，维护一个已覆盖的集合 $S$，每次加入连接 $S$ 与 $V-S$ 切集中代价最小的边。这是切集性质的直接应用。利用优先队列，复杂度为 $O(m \log n)$。
*   **Reverse-Delete (反向删除) 算法**：按权重降序遍历边，如果不导致图断开（即不破坏连通性）就将其删除。

#### 3. Borůvka 算法
*   **原理**：每个节点最初是一个连通分量。在每个阶段，对于每个蓝色的树（连通分量），在它的切集中找到代价最小的边并将其染成蓝色。然后将蓝色的树收缩成一个超节点。
*   **复杂度**：因为每次至少将节点数减半，所以最多运行 $\log_2 n$ 个阶段。时间复杂度为 $O(m \log n)$。
*   在平面图上运行的收缩版本可以达到 $O(n)$ 时间。结合 Prim，可得 $O(m \log \log n)$ 时间的混合算法。

#### 4. MST应用：单链聚类 (Single-link Clustering)

-   **问题定义**：聚类问题的本质是将一组对象分类到多个具有高度内部一致性的群组中。单链聚类算法的目标是最大化不同类簇之间的“间距”。
	*   **基本设定**：给定一个包含 $n$ 个对象的集合 $U = \{p_1, p_2, \dots, p_n\}$，我们需要将它们划分为 $k$ 个非空的子集（即类簇）。
	*   **距离函数 (Distance Function)**：用于衡量两个对象之间的“相似度”或“接近程度”。它必须满足三个自然属性：
	    1.  *同一性 (Identity of indiscernibles)*：$d(p_i, p_j) = 0$ 当且仅当 $p_i = p_j$。
	    2.  *非负性 (Nonnegativity)*：$d(p_i, p_j) \ge 0$。
	    3.  *对称性 (Symmetry)*：$d(p_i, p_j) = d(p_j, p_i)$。
	*   **间距 (Spacing)**：一个聚类方案的“间距”被定义为：**属于不同类簇的任意两个点之间的最小距离**。
	*   **优化目标 (Clustering of Maximum Spacing)**：给定整数 $k$，找到一个 $k$-聚类方案，使得其**间距最大化**。也就是说，我们要让不同的类簇之间离得尽可能远。

-   **算法的运行机制**：单链聚类算法的逻辑非常直观，它的核心就是“每次都把离得最近的两个不同类簇合并”。
	-   **算法步骤**：
	1.  初始状态下，将 $U$ 中的 $n$ 个对象看作 $n$ 个独立的类簇（图中表现为 $n$ 个孤立的节点）。
	2.  找到当前处于**不同类簇**中且距离最近的两个对象，在它们之间连一条边（即将这两个对象所在的类簇合并为一个新类簇）。
	3.  重复上述过程 $n - k$ 次，直到恰好剩下 $k$ 个类簇为止。
	-   这**恰好就是 Kruskal 算法**。唯一的区别是，Kruskal 算法会一直运行直到所有节点连通（形成 1 个类簇/1棵树），而单链聚类算法会在形成恰好 $k$ 个连通分量时“提前停止”。换句话说，单链 $k$-聚类的结果，完全等价于**先计算出整张图的最小生成树 (MST)，然后直接删去 MST 中权重最大的 $k-1$ 条边**。

-   **证明最优性（结构界限，反证法）**：
	-   **证明过程**：
		1.  **定义贪心解的状态**：令 $C^*$ 表示贪心算法得出的聚类方案（即删除了 MST 中最长的 $k-1$ 条边后剩下的聚类）。
		2.  **确定贪心解的间距 $d^*$**：因为我们删除了 MST 中最长的 $k-1$ 条边，所以 $C^*$ 的间距 $d^*$ 恰好等于被删除的这些边中**最短的那条边的长度**（这也是如果我们不提前停止，Kruskal 算法下一步即将添加的那条边的长度）。因此，MST 中保留下来的所有边的长度都必定 $\le d^*$。
		3.  **引入任意替代解进行比较**：假设存在另一个不同的聚类方案 $C$（它把对象分成了 $C_1, \dots, C_k$）。我们需要证明 $C$ 的间距绝对不可能大于 $d^*$。
		4.  **寻找矛盾点**：因为 $C$ 和 $C^*$ 是不同的聚类，必然存在两个对象 $p_i$ 和 $p_j$，它们在贪心解 $C^*$ 中属于**同一个**类簇（记为 $C^*_r$），但在替代解 $C$ 中却被分到了**不同**的类簇（记为 $C_s$ 和 $C_t$）。
		5.  **路径与跨簇边分析**：
		    *   既然 $p_i$ 和 $p_j$ 在 $C^*$ 中属于同一个类簇 $C^*_r$，说明在 MST 的这棵子树中，存在一条连接 $p_i$ 和 $p_j$ 的路径。
		    *   沿着这条路径从 $p_i$ 走到 $p_j$，既然起点在 $C$ 的类簇 $C_s$ 中，终点在 $C$ 的类簇 $C_t$ 中，那么在这条路径上，**必然至少存在一条边 $(p, q)$ 跨越了 $C$ 中的两个不同类簇**。
		    *   因为边 $(p, q)$ 是 $C^*_r$ 内部的边（即它是被 Kruskal 算法选中并保留下来的边），它的长度必然 $\le d^*$。
		6.  **得出结论**：在聚类方案 $C$ 中，我们找到了一对分属不同类簇的对象 $p$ 和 $q$，且它们之间的距离 $\le d^*$。根据间距的定义（不同簇间任意两点距离的最小值），聚类方案 $C$ 的间距必然 $\le d^*$。这证明了任何其他方案的间距都不会超过贪心方案 $C^*$ 的间距，故贪心算法是最优的。

### 六、 有向树问题：最小代价树形图 (Min-Cost Arborescences)
*   **概念**：给定有向图 $G$ 和根 $r$，找到以 $r$ 为根的有向生成树 (Arborescence)，且边权和最小。它要求从 $r$ 到所有其他节点都有唯一路径（除 $r$ 外每个节点的入度恰好为 1）。最短路径树不一定是最小代价树形图。
*   **降阶成本 (Reduced Costs)**：对除 $r$ 外的每个节点 $v$，设 $y(v)$ 是所有进入 $v$ 的边的最小代价。定义降阶成本为 $c'(u, v) = c(u, v) - y(v) \ge 0$。可以证明，原图的最小树形图和降阶成本下的最小树形图是同一个。
*   **贪心算法 (Edmonds Branching Algorithm)**：
    1.  对每个节点 $v \ne r$，挑出一条进入 $v$ 且降阶成本为 0 的边，构成集合 $F^*$。
    2.  如果 $F^*$ 不包含有向环，那么这就是最优的树形图。
    3.  如果 $F^*$ 包含一个有向环 $C$（全由0代价边组成），则将该环**收缩成一个超节点**，然后对收缩后的图递归调用算法，并最终将返回的树形图“解收缩”，去掉环上一条进入的边即可。
*   **关键证明性质 (Key Lemma)**：
    *   若 $G$ 中存在一个仅由 0 代价边构成的环 $C$，那么必然存在一个最小代价树形图 $T^*$，它**恰好只有一条边**进入该环 $C$。
    *   *证明技巧 (交换构造)*：如果存在多条边进入环 $C$。我们找到一条从根 $r$ 沿最短路径到达环 $C$ 并进入环的边 $(a, b)$。我们可以在 $T$ 中删除进入环其他节点的所有边，然后利用环 $C$ 上本身的 0 代价边补齐（除了进入 $b$ 的边不要）。由于我们只引入了 0 代价的边，且满足每个非根节点入度为 1 并且无环的性质，转化后的 $T^*$ 代价不升，且依然是合法的最小树形图。
    *   时间复杂度可达到 $O(mn)$，后续更高级的优化 (Gabow-Galil-Spencer-Tarjan) 甚至能达到 $O(m + n \log n)$。
