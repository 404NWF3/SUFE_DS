# 第二章：函数与库 (Functions and Libraries) 学习笔记

本章深入探讨了函数在编程中的核心地位，介绍了如何通过库（Libraries）来复用代码，并详细讲解了C++中函数的定义、调用机制、参数传递方式以及接口设计的原则。

## 1. 函数的基本概念 (The Idea of a Function)

### 1.1 数学与编程中的函数
*   **数学视角**：函数通常表示为一个公式，例如 $f(x) = x^2 + 1$，输入一个值得到一个结果。
*   **编程视角**：C++中的函数更为通用。它是一段被命名代码块，执行特定的计算任务。
    *   **调用 (Call)**：使用函数名来触发代码执行。
    *   **参数 (Arguments)**：传递给函数的信息。
    *   **返回 (Return)**：函数执行完毕回到调用点，通常带回一个结果。

### 1.2 使用函数的优势
1.  **复用性**：编写一次，多次使用，减少代码冗余。
2.  **易维护性**：只需修改一处代码即可更新所有调用处的逻辑。
3.  **分解 (Decomposition)**：将大型复杂问题分解为更小、更易管理的子问题（也称为自顶向下设计 Top-down design 或逐步求精 Stepwise refinement）。

### 1.3 函数与算法
函数是实现**算法 (Algorithms)** 的基础。算法是解决特定问题的精确策略。
*   **示例**：欧几里得算法（Euclid’s algorithm）用于计算最大公约数 (GCD)，是已知最早的非平凡算法之一。

---

## 2. 库 (Libraries)

现代编程极度依赖库。库将常用的功能打包，分为**接口 (Interface)** 和**实现 (Implementation)**。

*   **客户端 (Client)**：使用库的程序员。
*   **实现者 (Implementer)**：编写库的程序员。
*   **`<cmath>` 库**：C++标准数学库，提供了如 `sqrt` (平方根), `abs` (绝对值), `sin`, `cos`, `pow` (幂运算) 等函数。

---

## 3. 在 C++ 中定义函数

### 3.1 基本语法
```cpp
type name(parameters) {
    // 函数体
    // ...
    return expression;
}
```
*   **Predicate Function**：返回布尔值 (`bool`) 的函数通常被称为谓词函数，用于测试某种条件（如 `isEven(n)`）。
*   **Procedure**：返回类型为 `void` 的函数被称为过程，仅为了执行动作而不返回值。

### 3.2 函数原型 (Function Prototypes)
编译器需要在使用函数前知道其签名（参数类型和返回类型）。如果函数定义在调用之后，必须在文件顶部声明**原型**。
*   格式：`int raiseToPower(int n, int k);`。
*   本书惯例：除了 `main` 以外的所有函数都应提供原型，以便函数定义顺序更灵活。

### 3.3 重载 (Overloading)
C++ 允许定义多个同名函数，只要它们的**签名 (Signature)**（参数的数量或类型）不同。
*   示例：`abs(int x)` 和 `abs(double x)` 可以共存。

### 3.4 默认参数 (Default Parameters)
允许在原型中为参数指定默认值。如果调用时省略该参数，则使用默认值。
*   示例：`void formatInColumns(int nColumns = 2);`
*   规则：默认值只能在原型中指定，且必须位于参数列表的末尾。

## 4. 函数调用的机制 (Mechanics of Function Calls)

理解函数调用对于掌握递归至关重要。

### 4.1 调用步骤
1.  **参数求值**：计算调用时的实参表达式。
2.  **创建栈帧 (Stack Frame)**：系统为新函数分配内存块，用于存储局部变量和参数。
3.  **初始化参数**：将实参的值**复制**给形参。
4.  **执行**：运行函数体代码。
5.  **返回**：将返回值传回调用者，并**丢弃**栈帧（释放局部变量）。

### 4.2 组合数示例 (Combinations)
计算 $C(n, k) = \frac{n!}{k!(n-k)!}$ 的过程展示了多个栈帧的创建与销毁。
*   `main` 调用 `combinations`，`combinations` 调用 `fact`。
*   每次调用都会在栈顶压入一个新的帧，形成调用栈。

---

## 5. 引用参数 (Reference Parameters)

### 5.1 值传递 vs. 引用传递
*   **值传递 (Call by Value)**：默认行为。函数接收的是数据的**副本**。修改参数不会影响调用者。
*   **引用传递 (Call by Reference)**：在类型后加 `&`（如 `int &x`）。函数接收的是原始变量的**引用**（别名）。修改参数会直接改变调用者的变量。

### 5.2 引用传递的用途
1.  **改变数据**：例如 `swap(x, y)` 函数需要交换两个变量的值。
2.  **返回多个结果**：例如求解一元二次方程 `solveQuadratic`，需要通过参数返回两个根 (`x1`, `x2`)。
3.  **效率**：对于大型对象（如大字符串或向量），复制的代价很高。使用 `const` 引用（如 `const string & str`）既能避免复制，又能保证数据不被修改。

## 6. 接口与实现 (Interfaces and Implementations)

### 6.1 文件结构
*   **接口文件 (`.h`)**：包含函数原型、类型定义、常量定义。它是客户端和实现者之间的契约。
*   **实现文件 (`.cpp`)**：包含函数的具体代码。

### 6.2 接口样板 (Boilerplate)
为了防止头文件被重复包含，使用预处理指令：
```cpp
#ifndef _name_h
#define _name_h
// 接口内容
#endif
```
这是标准的接口编写规范。

### 6.3 导出类型与常量
*   接口可以定义枚举 (`enum`) 或类 (`class`) 供客户端使用。
*   导出常量需使用 `extern` 关键字（如 `extern const double PI;`），并在 `.cpp` 文件中进行赋值。

---

## 7. 接口设计原则 (Principles of Interface Design)

设计良好的接口应遵循以下标准：

1.  **统一性 (Unity)**：接口应围绕一个连贯的主题（如 `math.h` 全是数学函数）。
2.  **简洁性 (Simplicity)**：隐藏复杂的底层实现（**信息隐藏 Information Hiding**）。接口是客户端与实现之间的屏障。
3.  **充分性 (Sufficiency)**：必须提供足够的功能来满足客户需求。
4.  **通用性 (Generality)**：解决一类问题，而不是某个特定的应用场景。
5.  **稳定性 (Stability)**：接口一旦发布应保持稳定，改变接口会导致所有客户端代码崩溃，而改变实现通常不会。

## 8. 案例研究：随机数库 (`random.h`)

### 8.1 设计动机
标准库的 `rand()` 存在局限性（范围固定为 0 到 `RAND_MAX`，需要复杂的缩放和转换）。Stanford 库提供了更高层的抽象。

### 8.2 提供的功能
*   `randomInteger(low, high)`：返回 `[low, high]` 范围内的整数。
*   `randomReal(low, high)`：返回 `[low, high)` 范围内的浮点数（半开区间）。
*   `randomChance(p)`：以概率 `p` 返回 `true`。
*   `setRandomSeed(seed)`：设置种子，用于调试（使随机序列可重复）。

### 8.3 实现细节
*   **标准化**：先将 `rand()` 转换为 `[0, 1)` 的浮点数，再缩放和平移。
*   **初始化**：使用 `static bool initialized` 变量确保种子只在第一次调用时初始化（通常使用系统时间 `time(NULL)`）。

---

## 9. 案例研究：图形库 (`graphics.h`)

*   由于标准 C++ 缺乏简单的图形支持，Stanford 库提供了 `graphics.h`。
*   **坐标系**：原点 `(0, 0)` 在左上角，`x` 向右增加，`y` 向下增加。
*   **常用对象与函数**：
    *   `GWindow`：图形窗口对象。
    *   `drawRect`, `fillRect`：绘制矩形。
    *   `drawLine`, `drawOval`：绘制线条和椭圆。
    *   `drawString`：绘制文本。

---

## 总结
本章从微观的函数定义讲起，延伸到宏观的库设计。重点在于理解**抽象**的力量：通过精心设计的接口（如 `random.h` 和 `graphics.h`）隐藏复杂的实现细节，使程序员能够构建更复杂的系统。同时，掌握内存中的**栈帧**模型和**引用传递**是理解 C++ 程序行为的基础。
